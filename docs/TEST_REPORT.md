สภาพแวดล้อมที่ใช้ตรวจ: Linux, Node.js 24.19.0, MySQL 8.0.46 แยกฐานทดสอบจากฐานจริง การทดสอบ API ใช้ HTTP ผ่าน Supertest และคำสั่ง SQL ไป MySQL ไม่ใช่ mock database

รายการสำคัญที่ integration tests ครอบคลุม:

- Migration ซ้ำแล้วไม่สร้าง roles/admin ซ้ำ
- รหัส bootstrap บังคับเปลี่ยนและยกเลิก session เดิม
- สมัครปลอม Super ไม่ได้ บัญชี pending ใช้ระบบไม่ได้
- สมาชิกทั่วไปเข้า API จัดการสมาชิกไม่ได้ ห้ามถอด Super คนสุดท้าย
- ปีปฏิทินต้องยืนยันก่อนลา นำเข้า/แก้ไขวันหยุดแล้วกลับเป็นรอตรวจรับ
- CS และ Store ส่งวันศุกร์พร้อมกันแบบปกติ ผ่านเพียง 1 คน
- อนุมัติซ้ำไม่ได้ ยกเลิกแล้วโควตาว่างให้คนอื่น
- สมาชิกเปิดเหตุผลหรือรูปของคนอื่นไม่ได้ Super เปิดรูปแล้วมี audit
- ไฟล์ปลอมเป็นรูปถูกปฏิเสธ และบังคับเอกสารเมื่อถึงเกณฑ์
- ข้อมูลใน certificates เป็น ciphertext ส่วน API ส่ง JPEG ที่ถอดรหัสเฉพาะผู้มีสิทธิ์
- อนุมัติพิเศษต้องเลือกยืนยันและมีเหตุผล ห้ามอนุมัติของตนเอง
- ปฏิทินทีมไม่มีเหตุผลส่วนตัว ciphertext หรือ password_hash
- เรียก API ตรงยังถูกตรวจวันซ้ำ วันที่ไม่มีจริง และสิทธิ์คงเหลือ
- เปลี่ยนวันหยุดปกติที่มีวันลาอนาคตไม่ได้จนจัดการคำขอ
- OT ต้อง Store คนอื่นอนุญาต แล้ว Super อนุมัติ ไม่เพิ่มวันลาชดเชย
- รีเซ็ตรหัสยกเลิก session ทั้งหมดและบังคับเปลี่ยนรหัสใหม่

Unit tests ครอบคลุมการรวมวันหยุดปกติเฉพาะคน การแบ่งคำขอ วันหยุดเทศกาลทั้งสองด้าน ข้ามปี และการนับป่วยต่อเนื่องเพื่อไม่ให้แบ่งคำขอเลี่ยงเอกสาร

## ข้อจำกัดการตรวจครั้งนี้

- ไม่ได้รัน Docker Desktop / Docker Compose บน Mac ของผู้ใช้จริง จึงไม่อ้างว่าผ่านการ build Docker image หรือรัน MySQL image 8.4 แล้ว
- ไม่ได้ทดสอบ UI ด้วยเบราว์เซอร์อัตโนมัติ ตรวจ frontend ด้วย production build และโค้ด ไม่ใช่ภาพหน้าจอ
- ยังไม่ได้ Deploy เข้า account Cloudflare, Render, Aiven ของผู้ใช้ ไม่มีการอ้างว่าตั้งค่า TLS/CORS ของบัญชีจริงผ่านแล้ว
- รายการ Google มีวันสำคัญปะปนได้ การอ่านได้ 28 รายการไม่ได้แปลว่าทุกวันเป็นวันหยุดขององค์กร
- ผล npm audit เป็นสถานะของแพ็กเกจ ณ วันตรวจ ไม่ใช่การรับรองว่าไม่มีช่องโหว่ทุกชนิด

## ทดสอบในเครื่อง

หลังติดตั้ง Node.js ตาม README และ `npm ci`:

```bash
npm run check
npm test
npm run build
npm audit
```

ต้องการ integration tests กับ MySQL 8.4 แบบฐานทิ้งได้ แยกจากโปรเจกต์จริงและใช้ Docker:

```bash
bash scripts/test-integration.sh
```

สคริปต์สร้าง Compose project ชื่อสุ่ม ไม่มีการเปิด port MySQL ของ test ออกเครื่อง host ไม่อ่าน `.env` ของระบบจริง ใช้ฐาน `scm_leave_test` และเก็บ datadir เป็น tmpfs เมื่อเสร็จจะลบเฉพาะทรัพยากร test project ที่ตนสร้าง

หากใช้ MySQL server ทดสอบที่มีอยู่ ต้องเตรียมฐานว่างชื่อ `scm_leave_test` โดยเฉพาะ แล้วกำหนด environment เอง:

```bash
RUN_INTEGRATION=1 \
DB_NAME=scm_leave_test \
DB_HOST=127.0.0.1 \
DB_PORT=3306 \
DB_USER=YOUR_TEST_USER \
DB_PASSWORD=YOUR_TEST_PASSWORD \
npm run test:integration --workspace api
```

ไฟล์ทดสอบจะหยุดทันทีถ้า RUN_INTEGRATION ไม่ใช่ 1, DB_NAME ไม่ตรงชื่อที่กำหนด หรือฐานไม่ว่าง ไม่ drop/truncate ตารางให้เอง หลังทดสอบสำเร็จฐานจะมีข้อมูลตัวอย่างของการทดสอบ จึงต้องเตรียมฐานทดสอบใหม่ก่อนรันรอบต่อไป

## ตรวจรับก่อนใช้งานกับทีม

1. รันในเครื่องและเข้าด้วย Super เปลี่ยนรหัสสำเร็จ
2. ยืนยันปฏิทินตามประกาศองค์กร และกำหนดสิทธิ์รายปี
3. สมัคร CS/Store คนละบัญชี เปิดใช้งาน ตรวจวันหยุดต่างกัน
4. ทดลองส่งวันลาและให้คนอื่นอนุมัติ ดูผลบนปฏิทิน 4 มุมมอง
5. ทดลองลาป่วยพร้อมรูปและสิทธิ์เปิดรูปจากคนละบัญชี
6. ทดลอง Backup และทดสอบ Restore ในฐานแยก เก็บ FILE_ENCRYPTION_KEY เดิม
7. หลัง Deploy ตรวจ /health, login, CORS และรีเฟรช URL /requests
