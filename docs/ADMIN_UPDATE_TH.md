# อัปเดต Admin สำหรับ SCM Leave 1.1

## พฤติกรรมใหม่

- Admin ดูปฏิทิน จัดการสมาชิก วันหยุด กติกา ประวัติ และพิจารณาคำขอลา/งานแทนของสมาชิกได้
- Admin ไม่ต้องกำหนดวันหยุดปกติหรือสิทธิ์รายปี ไม่แสดงวันหยุดส่วนตัวในปฏิทินและไม่ถูกนับในกำลังคนของทีม
- Admin ไม่ส่งคำขอลาหรือทำงานแทนของตนเอง ทั้งหน้าจอและ API ป้องกันไว้
- Super Customer Service ยังเป็นสมาชิกที่มีวันหยุดและขอลาได้ Admin หรือ Super คนอื่นพิจารณาคำขอของ Super ได้
- OT ยังต้องให้ Store คนอื่นอนุญาตก่อน Admin / Super อนุมัติ ห้ามอนุมัติรายการของตนเอง
- หน้าสมัครสาธารณะยังเลือกได้เฉพาะ CS / Store บัญชีทั่วไปเพิ่มสิทธิ์ตนเองไม่ได้

## อัปเดตโปรเจกต์เดิมบน Mac

ดาวน์โหลด `scm-leave-admin-update-v1.1.zip` ไปไว้ Downloads เปิด Terminal แล้วรันคำสั่งเดียวนี้:

```bash
unzip -o "$HOME/Downloads/scm-leave-admin-update-v1.1.zip" -d "$HOME/Downloads" && bash "$HOME/Downloads/scm-leave-admin-update/install.sh" "$HOME/Downloads/scm-leave" --push
```

สคริปต์ตรวจความเข้ากันได้และสำรองเฉพาะไฟล์ที่จะเปลี่ยนก่อนติดตั้ง จากนั้นสร้าง commit และ Push เฉพาะไฟล์อัปเดตไป `origin/main` ไม่แตะ `.env` รหัสผ่าน หรือ FILE_ENCRYPTION_KEY เมื่อใช้ `--push` ต้องอยู่บน branch main และไม่มีการแก้ไขไฟล์ tracked หรือไฟล์ staged ค้างไว้ ให้ commit งานเดิมแยกก่อนถ้ามี สคริปต์ไม่ใช้ force push

หากต้องการติดตั้งเพื่อตรวจโค้ดก่อน ให้ตัด `--push` ออก แล้วใช้ `git diff` ตรวจความเปลี่ยนแปลง สคริปต์ไม่รันคำสั่ง SQL ไปฐานจริงจากเครื่องคุณ

หากติดตั้งโดยไม่ใช้ `--push` แล้วต้องการส่งขึ้น GitHub ให้ตรวจ `git diff` และ `git status` ก่อน จากนั้นใช้รายการไฟล์ใน `CHANGED_FILES.txt` ของชุดอัปเดตเพื่อเลือก commit งานนี้ หาก Push ล้มเหลวหลังสร้าง commit แล้ว ให้แก้สาเหตุที่ Git แจ้งแล้วรัน `git push origin main` ซ้ำ ไม่ต้องติดตั้งใหม่

หากสคริปต์แจ้งว่าไฟล์ไม่ตรงกับรุ่นเดิม ให้หยุดและตรวจข้อความ ไม่ควรคัดลอกไฟล์ทับการแก้ของคุณโดยไม่ตรวจ diff ส่งข้อความผิดพลาดให้ผู้ดูแลปรับ patch ให้ตรงกับรุ่นที่ใช้อยู่ได้

## Deploy บนระบบที่ใช้อยู่

1. ตรวจใน Aiven ว่าบริการ MySQL เป็น Running ก่อน เพื่อให้ migration เชื่อมฐานได้
2. หลัง Push เปิด https://dashboard.render.com/ เลือก scm-leave-api รอ Deploy ล่าสุดเป็น Live หากปิด Auto Deploy ให้กด Manual Deploy แล้ว Deploy latest commit
3. API รัน migration 001 และ 002 ตอนเริ่ม Docker อัตโนมัติ migration 002 เพิ่มแถว ADMIN ในตาราง roles และบันทึกเวอร์ชัน ไม่มีการ Drop หรือสร้างฐานใหม่
4. เปิด https://dash.cloudflare.com/ ไป Compute แล้ว Workers & Pages เลือกโปรเจกต์ scmleave รอ Production deployment ล่าสุดสำเร็จ หากไม่มี Build ใหม่ ให้ Retry deployment ของ main หรือสร้าง deployment ใหม่จาก commit ล่าสุด
5. คงค่า Build command เป็น `npm ci && npm run build` และ output เป็น `web/dist` ค่า NODE_VERSION เป็น 24
6. คง VITE_API_URL เป็น https://scm-leave-api.onrender.com/api และ Render CORS_ORIGINS เป็น https://scmleave.pages.dev ไม่ต้องเปลี่ยนค่าฐานข้อมูลหรือกุญแจไฟล์
7. เปิด https://scmleave.pages.dev แล้วรีเฟรช หากเห็นหน้าเก่าให้ใช้ Command Shift R และเข้าสู่ระบบใหม่

Render และ Cloudflare อาจ Deploy เสร็จต่างเวลากัน ให้รอทั้งสองบริการก่อนทดสอบปุ่มเพิ่ม Admin ไม่ต้อง Import SQL ด้วย phpMyAdmin หาก migration สำเร็จแล้ว

## ใช้บัญชีเดิมเป็น Admin

ฐานที่ใช้งานอยู่จะไม่เปลี่ยน Super เดิมเป็น Admin โดยอัตโนมัติ เพื่อคงบทบาทและรหัสผ่านเดิมของทีม

1. เข้าด้วย Super เดิม ไป สมาชิกในทีม แล้วกดดินสอข้างบัญชีของคุณ
2. เปลี่ยนตำแหน่งเป็น Admin ช่องวันหยุดและสิทธิ์รายปีจะซ่อน
3. หากมีคำขอรออนุมัติหรือวันลา/งานแทนในอนาคตที่ยังใช้งานอยู่ ต้องยกเลิกรายการที่เกี่ยวข้องก่อน ถ้ามีงานแทนผูกกับวันลาให้ยกเลิกงานแทนก่อน
4. กดบันทึกข้อมูลสมาชิก แล้วเข้าสู่ระบบใหม่ด้วยอีเมลและรหัสผ่านเดิม
5. ตรวจในบัญชีของฉันว่าแสดง Admin และข้อความว่าไม่ต้องกำหนดวันหยุด ปุ่มสร้างคำขอลาและขอทำงานแทนจะไม่แสดง

ตารางวันหยุด สิทธิ์ และคำขอเก่ายังคงอยู่สำหรับประวัติ Admin ไม่ถูกนำไปแสดงเป็นกำลังคน การเปลี่ยนกลับเป็น Super / CS / Store ต้องกำหนดวันหยุดและวันเริ่มใช้ตารางใหม่

## เพิ่ม Admin อีกบัญชีโดยตรง

1. เข้าด้วย Admin หรือ Super แล้วเปิด สมาชิกในทีม
2. กด เพิ่ม Admin กรอกชื่อและอีเมลใหม่ที่ยังไม่เคยใช้ แล้วกด สร้างบัญชี Admin
3. จดรหัสชั่วคราวที่แสดงครั้งเดียวและส่งให้เจ้าของบัญชีเป็นการส่วนตัว
4. บัญชีใหม่ใช้งานได้ทันทีโดยไม่ต้องเลือกวันหยุด และต้องเปลี่ยนรหัสเมื่อเข้าสู่ระบบครั้งแรก

สำหรับฐานติดตั้งใหม่ตั้งแต่รุ่นนี้ บัญชี BOOTSTRAP_ADMIN_* จะถูกสร้างเป็น Admin โดยไม่มีตารางวันหยุด ส่วนฐานเดิมที่มี Admin หรือ Super แล้วจะไม่สร้างบัญชีซ้ำและไม่เปลี่ยนรหัสเดิม

## ทดสอบหลัง Deploy

- บัญชีเดิมเข้าสู่ระบบและดูประวัติได้
- Admin เปิดเมนูจัดการและอนุมัติคำขอของผู้อื่นได้ แต่ไม่มีปุ่มสร้างวันลาหรือวันหยุดส่วนตัวในปฏิทิน
- CS / Store ยังคงส่งคำขอลาและเห็นวันหยุดของตนเองตามเดิม
- Super ส่งคำขอลาของตน แล้วให้ Admin พิจารณาได้
- Store ยังเป็นผู้อนุญาต OT ก่อนผู้ดูแลอนุมัติ
- หน้าสมัครไม่มีตัวเลือก Admin หรือ Super

## อาการที่อาจพบ

- เพิ่ม Admin ไม่ได้หรือ API 404: รอ API รุ่นล่าสุด Deploy สำเร็จก่อน
- บันทึกบทบาทแล้วเซสชันหมดอายุ: เป็นผลจากการเปลี่ยนสิทธิ์ ให้เข้าสู่ระบบใหม่
- เปลี่ยนเป็น Admin ไม่ได้เพราะมีคำขอ: จัดการคำขอที่ระบบแจ้งก่อน ประวัติไม่ถูกลบ
- Render ขึ้น Exited with status 1: ตรวจ Logs และสถานะฐาน Aiven ให้ Running ก่อน Deploy ใหม่ การเพิ่ม role ไม่แก้ปัญหาฐานที่ Powered off
