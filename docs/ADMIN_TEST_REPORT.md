## กรณีสำคัญที่ตรวจ

- ฐานใหม่สร้าง bootstrap เป็น ADMIN และไม่มี work_schedules
- สมัครผ่านหน้าสาธารณะปลอม role ADMIN / SUPER_CS ไม่ได้
- CS / Store เข้า API จัดการหรือสร้าง Admin ไม่ได้
- Admin สร้างและอนุมัติรายการของสมาชิก ดูเอกสาร และจัดการระบบได้
- Admin ส่งคำขอลา preview / multipart หรือทำงานแทนผ่าน API โดยตรงไม่ได้
- Admin ไม่มี schedules ใน meta ไม่มี balances ไม่อยู่ใน people หรือสมาชิกในปฏิทิน และถูกเลือกเป็นผู้ถูกทำงานแทนไม่ได้
- เปลี่ยน Super เป็น Admin ได้โดยไม่กรอกวันหยุด รหัสเดิมยังใช้ได้ และ session เก่าถูกเพิกถอน
- ตารางประวัติเดิมยังอยู่ เมื่อเปลี่ยน Admin กลับเป็น Super ต้องระบุวันหยุดและวันเริ่มตาราง
- เพิ่ม Admin ด้วยชื่อและอีเมล คืนรหัสชั่วคราว บังคับเปลี่ยนครั้งแรก และป้องกันอีเมลซ้ำ
- ห้ามลดสิทธิ์หรือระงับผู้ดูแลคนสุดท้ายจนระบบไม่มี Admin / Super ที่ใช้งานได้
- เปลี่ยนสมาชิกเป็น Admin ไม่ได้หากยังมีคำขอที่ต้องจัดการ
- Super อนุมัติคำขอของตนเองไม่ได้ แต่ Admin อนุมัติให้ได้
- Admin ข้ามขั้น Store อนุญาต OT ไม่ได้
- เงื่อนไขเดิมเรื่องวันหยุดไทย โควตา การส่งพร้อมกัน ใบรับรอง และการรีเซ็ตรหัสยังผ่าน

## ขอบเขตการยืนยัน

ยังไม่ได้ทดสอบหน้า UI ด้วยเบราว์เซอร์อัตโนมัติ และไม่ได้รัน Docker Desktop บน Mac ของผู้ใช้ การตรวจหน้าเว็บครั้งนี้ใช้ production build และตรวจโค้ด สิ่งที่ทดสอบกับฐานจริงทำใน MySQL 8.0.46 ไม่ใช่การอ้างว่ารันทดสอบบน Aiven 8.4 แล้ว

ชุดอัปเดตยังไม่ได้ถูก Push ไป GitHub หรือ Deploy เข้า Render / Cloudflare ของผู้ใช้ ต้องรันคำสั่งติดตั้งและรอทั้ง API กับเว็บ Deploy สำเร็จก่อนใช้บทบาทใหม่
