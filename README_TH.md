# SCM Leave — ระบบปฏิทินและจัดการวันลา

โปรเจกต์เต็มสำหรับ React + MUI, Node.js + Express และ MySQL พร้อม phpMyAdmin, Docker Compose และคู่มือ Deploy Cloudflare Pages + Render + Aiven

UI เขียนใหม่โดยใช้ MUI ในแนวทางแดชบอร์ด Minimals: เมนูด้านซ้าย พื้นสว่าง สีเขียว การ์ด และฟอร์ม Modal ไม่ได้รวมซอร์สของเทมเพลต Minimals แบบเสียเงิน

## ติดตั้งบน Mac ด้วยคำสั่งเดียว

ติดตั้งและเปิด [Docker Desktop](https://www.docker.com/products/docker-desktop/) ไว้ก่อน ไม่จำเป็นต้องมี Node.js/MySQL บน Mac

เมื่อดาวน์โหลด `scm-leave-complete-v1.zip` ไว้ใน Downloads เปิด Terminal แล้ววาง:

```bash
cd "$HOME/Downloads" && unzip -n scm-leave-complete-v1.zip && bash scm-leave/scripts/start.sh
```

คำสั่งนี้แตกไฟล์ สร้างรหัสลับแบบสุ่ม Build และเปิดบริการทั้งหมด พร้อมเปิดเบราว์เซอร์ให้ ครั้งแรกต้องใช้อินเทอร์เน็ตและรอโหลด Docker images / npm packages รันซ้ำแล้วข้อมูลเดิมยังอยู่ ไม่เปลี่ยนรหัสบัญชีเดิม

| บริการ | URL เริ่มต้น |
|---|---|
| เว็บแอป | http://localhost:5173 |
| API health | http://localhost:4000/health |
| phpMyAdmin | http://localhost:8088 |
| MySQL จากโปรแกรมใน Mac | 127.0.0.1:3307 |

บัญชี Super เริ่มต้น: `admin@scm.local` รหัสผ่านสุ่มจะแสดงใน Terminal หลังเริ่มสำเร็จ เก็บไว้ใน `.env` เฉพาะเครื่องของคุณ และบังคับให้เปลี่ยนรหัสเมื่อเข้าใช้ครั้งแรก ไม่มีรหัส Admin ตายตัวในซอร์สโค้ด

phpMyAdmin ใช้ username `scm` และ DB_PASSWORD ที่สคริปต์แสดง ไม่ใช้รหัสบัญชีเว็บ ค่าเริ่มต้นเปิดบริการเฉพาะเครื่องตัวเอง (`127.0.0.1`)

## เริ่มใช้งานครั้งแรก

1. เข้าสู่ระบบด้วยบัญชีเริ่มต้น เปลี่ยนรหัส แล้วเข้าสู่ระบบใหม่
2. เปิด “วันหยุดไทย” ตรวจรายการของปีปัจจุบัน เทียบประกาศองค์กร เพิ่ม/ปิดวันหยุดตามจริง
3. ใช้ “ดูรายการจากปฏิทินไทยออนไลน์ (Google)” เพื่อดูข้อมูลของปีนั้น เลือกนำเข้าเฉพาะวันหยุดจริง รายการอาจมีวันสำคัญที่บริษัทไม่ได้หยุด
4. กรอกแหล่งอ้างอิง/ประกาศที่ตรวจแล้ว กด “ยืนยันปฏิทิน” ตรวจปีข้างเคียงด้วยเมื่อหยุดข้ามปี
5. ให้สมาชิกสมัคร เลือกตำแหน่ง CS หรือ Store และวันหยุดประจำสัปดาห์ เช่น ศุกร์–เสาร์ / อาทิตย์–จันทร์
6. Super เปิด “สมาชิกในทีม” เปลี่ยนสถานะบัญชีเป็น “ใช้งาน” ตรวจตำแหน่งและวันหยุดให้ถูกต้อง
7. ถ้าต้องการเพดานรายปี ให้กำหนดสิทธิ์วันลาแต่ละประเภทในหน้าสมาชิก ค่าเริ่มต้นยังไม่กำหนดสิทธิ์ ไม่มีการสมมติวันลาตามอายุงาน
8. สมาชิกคลิกวันที่/ลากช่วงในปฏิทิน หรือกด “สร้างคำขอลา” ตรวจเงื่อนไข แล้วส่งคำขอ
9. Super อีกคนเป็นผู้อนุมัติ คำขอของตนเองไม่สามารถอนุมัติ/ปฏิเสธเองได้

ถ้ามี Super เพียงคนเดียว ให้ผู้ดูแลเปิดใช้งานสมาชิกที่ได้รับมอบหมายอีกคน และเปลี่ยนตำแหน่งเป็น Super ก่อนจะอนุมัติวันลาของ Super คนแรก

## สิ่งที่รวมมา

- สมัครสมาชิก / เข้าสู่ระบบ / ออกจากระบบ / เปลี่ยนรหัส / ผู้ดูแลสร้างรหัสชั่วคราว
- 3 ตำแหน่ง: Super Customer Service, Customer Service, Store
- ปฏิทินรายวัน สัปดาห์ เดือน ปี ค้นหาสมาชิก เลือกคน กรองวันหยุดปกติและคำขอรออนุมัติ พิมพ์ปฏิทิน
- แยกวันหยุดปกติของแต่ละคน พร้อมประวัติและวันเริ่มใช้ตารางใหม่
- ลาพักร้อน ลากิจ ลาป่วย ตรวจเงื่อนไขจาก API ทั้งตอนส่งและอนุมัติ
- ตรวจคำขอที่แบ่งช่วง ป้องกันลาซ้ำ จองโควตาระหว่างรออนุมัติ และป้องกันส่งพร้อมกันเกินโควตา
- ยกเลิกคำขอ คืนโควตา และเก็บประวัติ ไม่มีการลบรายการอนุมัติทิ้งจากฐานข้อมูล
- แนบรูปใบรับรองแพทย์ JPEG/PNG/WebP สูงสุด 8 MB, 20 ล้านพิกเซล ปรับขนาด ลบ metadata แล้วเข้ารหัสเก็บใน MySQL
- รูปใบรับรองและเหตุผลดูได้เฉพาะเจ้าของคำขอและ Super ไม่ส่งไปพร้อมข้อมูลปฏิทินทีม
- วันหยุดไทยคำนวณตามปี + นำเข้า Google Thai holidays + แก้วันหยุดพิเศษ + ยืนยันปฏิทิน
- สิทธิ์วันลารายคน/ปี/ประเภท ยอดใช้แล้ว/จองไว้/คงเหลือ
- ขอทำงานแทน ไม่สร้าง OT/วันชดเชยอัตโนมัติ ถ้าขอ OT ต้องให้ Store อนุญาตก่อน Super อนุมัติ
- Audit log การเปลี่ยนสิทธิ์ คำขอ วันหยุด รหัสผ่าน และการเปิดใบรับรอง
- SQL Schema, migrations ที่รันซ้ำได้, ทดสอบกฎ/ความปลอดภัย, integration tests, Dockerfiles และ Render Blueprint

| กติกา | วิธีตรวจ |
|---|---|
| ศุกร์/เสาร์/อาทิตย์ ลาเพิ่มได้ 1 คนต่อวัน รวม Store | รวมคำขอ pending + approved ทั้งทีม วันหยุดปกติไม่กินโควตาลาเพิ่ม |
| จำเป็นต้องเกินโควตาจริง ๆ | ต้องคุยในทีม เลือกขออนุมัติพิเศษ ระบุเหตุจำเป็น แล้วให้ Super ยืนยันข้อยกเว้น |
| วันหยุดปกติ + ลาเพิ่ม ≤4 วัน | นับช่วงหยุดต่อเนื่องจริง รวมคำขอเดิมที่อยู่ติดกัน |
| จำเป็น 5 วัน | ต้องคุยทีม + แจ้งพี่เกล้า + เหตุจำเป็น + Super ยืนยันพิเศษ |
| มากกว่า 5 วัน | วันลาทั่วไปถูกปฏิเสธ; ลาป่วยส่งขอพิจารณาพิเศษได้ |
| เทศกาล + วันหยุดปกติ | วันหยุดเองแสดงบนปฏิทินได้ ห้ามต่อวันลาทั่วไปทั้งก่อนและหลัง รวมช่วงที่เชื่อมด้วยวันหยุดปกติ |
| ลาป่วย 1 วัน | ไม่บังคับใบรับรอง |
| ลาป่วย 2 วัน | ค่าเริ่มต้นไม่บังคับ ตามข้อความ “เกิน 2 วัน”; ผู้ดูแลปรับเป็นตั้งแต่ 2 วันได้ |
| ลาป่วยตั้งแต่ 3 วัน | ต้องแนบใบรับรองในคำขอนั้น นับวันปฏิทินและคำขอป่วยต่อเนื่องที่แบ่งช่วง |
| OT / วันชดเชย | ไม่มีการสร้างอัตโนมัติ OT ต้อง Store อนุญาตก่อน; ไม่มีประเภทลาชดเชย |

ลาป่วยที่ชนข้อจำกัดเพื่อวางแผนทีม (จำนวนคน/ติดเทศกาล/ระยะยาว/สิทธิ์ไม่พอ/ปีที่ยังไม่ยืนยัน) ส่งขออนุมัติพิเศษได้ มีเหตุผลและให้ Super รับรองเป็นรายกรณี เอกสารแพทย์ที่จำเป็นยังต้องแนบ

## คำสั่งดูแลในเครื่อง

จากโฟลเดอร์ `scm-leave`:

```bash
# ดูสถานะ
docker compose ps

# ดู log API
docker compose logs -f --tail=80 api

# หยุด โดยเก็บ volume และข้อมูลเดิม
docker compose down

# เปิดอีกครั้ง
bash scripts/start.sh

# สำรองฐานข้อมูล (รวมรูปใบรับรองที่เข้ารหัส)
bash scripts/backup.sh
```

ไม่ใช้ `docker compose down -v` หากยังต้องการข้อมูลเดิม เพราะ `-v` ลบฐานข้อมูลใน volume ด้วย

รันแล้วพอร์ตชน: แก้ `WEB_PORT`, `API_PORT`, `PMA_PORT`, `MYSQL_PORT` ใน `.env` แล้วรัน `bash scripts/start.sh` ใหม่ ถ้าเปลี่ยน WEB_PORT ให้เปลี่ยน `CORS_ORIGINS=http://localhost:พอร์ตใหม่` ด้วย

เปลี่ยนพอร์ต API แล้ว image เว็บจะถูก build ใหม่ให้ชี้พอร์ตใหม่อัตโนมัติ อย่าเปลี่ยน DB_PASSWORD/MYSQL_ROOT_PASSWORD ใน `.env` หลัง MySQL มีข้อมูลแล้วโดยไม่เปลี่ยนรหัสใน MySQL ด้วย

## พัฒนาโค้ดโดยใช้ Node.js

ต้องมี Node.js 24 LTS หรือ 22.12+ และ npm จากนั้น:

```bash
# หลังเริ่ม Docker ไว้แล้ว ต้องหยุด web/api เพื่อไม่ให้ชนพอร์ต
docker compose stop api web
npm ci
npm run migrate

# Terminal ที่ 1
npm run dev --workspace api

# Terminal ที่ 2
npm run dev --workspace web
```

API ใช้ค่า `.env` ที่ root (DB_HOST=127.0.0.1, DB_PORT=3307) เว็บ dev ใช้ `http://localhost:4000/api` หรือกำหนด `web/.env` จาก `web/.env.example`

```bash
npm run check
npm test
npm run build
npm audit
```

Integration tests ต้องใช้ฐานข้อมูลทดสอบแยกเท่านั้น ดูคำสั่งใน [docs/TEST_REPORT.md](docs/TEST_REPORT.md)

## ขอบเขตการใช้งาน

- รองรับวันลาเต็มวัน ยังไม่มีครึ่งวัน/รายชั่วโมง
- หนึ่งองค์กร/หนึ่งทีม ใช้โควตาร่วมทั้ง CS และ Store ไม่ได้แยกโควตาให้ทีม Boost up
- หน้าคำขอแสดง 500 รายการล่าสุด หน้าทำงานแทน 300 รายการ และ Audit 200 รายการ ข้อมูลที่เก่ากว่ายังคงอยู่ใน MySQL
- แก้วันลาที่ส่งไปแล้วด้วยการยกเลิกแล้วส่งใหม่ เพื่อเก็บประวัติการตรวจเดิม
- ไม่รวมระบบส่งอีเมล, SSO, คิดเงินเดือน, อัตรา OT, สลิป หรือการโอนวันลาข้ามปี
- ปฏิทินออนไลน์ต้องมีข้อมูลของปีนั้น และอาจเชื่อมต่อไม่ได้ รายการคำนวณและการเพิ่มตามประกาศยังใช้ได้
- วันหยุดพิเศษและปฏิทินขององค์กรต้องมีผู้ดูแลตรวจรับ ไม่สมมติว่าวันหยุดธนาคารทั้งหมดเป็นวันหยุดบริษัท
- โค้ดไม่ได้ Deploy ไปบัญชี Cloudflare/Render/Aiven ของคุณให้อัตโนมัติ ใช้คู่มือพร้อมค่าตั้งต้นในชุดนี้เพื่อดำเนินการในบัญชีของคุณ
